# Ustalenia i wnioski

To indeks pamięci długoterminowej projektu. Przeczytaj go przed rozpoczęciem pracy, a następnie otwórz opisy dotyczące bieżącego zadania.

Krótkie wnioski zapisuj poniżej. Dłuższe opisy umieszczaj w `lessons/slug.md` i dodawaj tutaj link z krótkim podsumowaniem. Każdy wniosek powinien zawierać datę, kontekst, przyczynę, sprawdzone rozwiązanie i sposób zapobiegania lub weryfikacji. Hipotezy oznaczaj wyraźnie. Aktualizuj istniejące ustalenia zamiast tworzyć duplikaty.

## Indeks

- **2026-11-03 — środowisko a bundler Next.js:** statyczne `new URL('../../../.env', import.meta.url)` w module `db` zostało potraktowane przez Turbopack jako import zasobu i przerwało build. Sprawdzone rozwiązanie: ładować root `.env` w `next.config.ts` i wejściach CLI, a w modułach bazy czytać `process.env`. Weryfikacja: build bez pliku `.env` i bez `DATABASE_URL` oraz rzeczywisty `db:check` z konfiguracją środowiska.
- **2026-11-03 — scope DI podczas prerenderingu:** `randomUUID()` wywołane przy tworzeniu scope blokowało prerendering z Cache Components, nawet gdy strona czytała tylko stałe informacje o aplikacji. Generowanie metadanych żądania jest teraz leniwe (resolver scoped), dopiero przy użyciu. Weryfikacja: produkcyjny build statycznej strony oraz test stabilności i izolacji identyfikatora w równoległych scope.
- **2026-11-03 — MikroORM 7:** zainstalowane API inicjalizuje metadane bez otwierania połączenia; `connect: false` nie jest już opcją konfiguracji. Sukces inicjalizacji lub testów bez bazy nie potwierdza połączenia. Weryfikuj integrację przez rzeczywiste zapytanie, np. `npm run db:check` (`SELECT 1`), i korzystaj z deklaracji wersji zainstalowanej w repozytorium.


- **2026-11-03 — zgodność narzędzi lint:** mimo ogólnego peer `eslint >=9` w eslint-config-next 16.4.4, dołączone eslint-plugin-import 2.32, jsx-a11y 6.10 i react 7.37 deklarują wsparcie tylko do ESLint 9. ESLint 10 przechodził lint, ale `npm ls eslint` zgłaszało invalid peers. Pozostawiono zgodny ESLint 9.39.5 (rejestr oznacza tę wersję jako niewspieraną); przy aktualizacji sprawdzać cały graf peer dependencies, nie tylko sukces lint, i nie wymuszać instalacji przez `--force`.


- **2026-11-03 — routing zależności shadcn w monorepo:** komponent Button nie ujawnił błędnego aliasu hooków aplikacji. Przy dodaniu sidebar CLI kierował współdzielony komponent do ui, ale hook do app i generował zabroniony import ui → app. Sprawdzone rozwiązanie: alias hooków app/ui wskazuje `@devmentor/ui/hooks`, a pakiet ui eksportuje publicznie `./hooks/*` i `./lib/*`. Przy zmianie konfiguracji sprawdzaj dry-run i importy komponentu z zależnościami, nie tylko prostego Button.
- **2026-11-03 — gotowość lokalnego PostgreSQL:** `docker compose up -d` potwierdza uruchomienie kontenera, ale nie koniec initdb i gotowość połączeń. `db:up` używa `--wait --wait-timeout 120` wraz z healthcheckiem, aby następujące po nim `db:check` nie ścigało się z pierwszą inicjalizacją bazy.

- **2026-11-03 — skip link w prototypie z routingiem hash:** zwykły link do `#main` uruchamiał router i zmieniał ekran zamiast przenosić fokus. Rozwiązanie: przechwycić kliknięcie skip link przez `preventDefault()`, ustawić fokus na `main` z `tabindex="-1"` i pozostawić hash bez zmiany. Zweryfikowano klawiaturą (Enter): fokus na `main`, trasa zachowana. Dotyczy samodzielnych makiet z routerem hash; nie przenosić mechanicznie na router Next.js.

- **2026-11-03 — integralność holdów i sesji:** research projektowanego terminarza wykazał, że osobne constraints w tabelach holdów i sesji nie chronią konfliktu między tabelami. Zalecenie: wspólna reprezentacja aktywnego zajęcia czasu, exclusion constraint i jawne wygaszanie stanu. Nie używać now() w predykacie indeksu — PostgreSQL wymaga immutable, a indeks nie zmienia wpisów wraz z upływem czasu ([dokumentacja](https://www.postgresql.org/docs/18/sql-createindex.html)). Wdrożono wspólną tabelę bookings oraz constraint no_overlapping_mentor_bookings dla held/confirmed w Migration202611030001; holdy i potwierdzone sesje nie są oddzielnymi tabelami. Testy integracyjne PostgreSQL sprawdzają konkurencyjne rezerwacje, wygaśnięcie i późną płatność. Przy kolejnych zmianach ponawiaj migracje i te scenariusze na realnej bazie; nie zastępuj ochrony SQL odczytem dostępności. Szczegóły: [specyfikacja, sekcja 6](specs/2026-11-03-engineering-standards.md).

- **2026-11-03 — Vitest i rzeczywisty warunek server-only:** przy przejściu z node:test do Vitest samo `resolve.conditions`/execArgv nie wystarczało dla zewnętrznego modułu. Sprawdzone rozwiązanie w aktualnym Vitest/Vite: warunki `react-server` w resolverze Vite/SSR oraz `server.deps.inline: ["server-only"]`, aby użyć rzeczywistego eksportu warunkowego zamiast mocka. Weryfikacja: testy serwerowych scope przechodzą bez mockowania granicy. Konfigurację należy ponownie sprawdzić przy aktualizacji Vitest.

- **2026-11-03 — daty z surowych zapytań PostgreSQL:** driver używany przez MikroORM zwrócił `timestamptz` jako tekst inny niż kanoniczne ISO UTC, co psuło kontrakt DTO i porównania w UI/testach. Sprawdzone rozwiązanie: normalizować jawne pola dat na granicy repozytorium przez parsowanie i `toISOString()`, nie przekształcać dowolnych tekstów użytkownika. Weryfikacja: integracja realnego PostgreSQL, UTC/offset i cykliczna dostępność IANA.

- **2026-11-03 — pełne coverage i środowiska React:** próg obejmujący tylko core ukrywał nieprzetestowane adaptery i komponenty. Vitest ma osobne projekty server (`react-server`, rzeczywisty `server-only`) i client (jsdom), a coverage zbiera wszystkie pliki implementacji także bez importów i egzekwuje cztery metryki per plik. Weryfikacja: pełny raport i celowo dodany nieimportowany plik powodujący błąd progu. Typecheck pakietu ui musi widzieć typy matcherów przez import `@testing-library/jest-dom/vitest` w jego testach.
- **2026-11-03 — odczytane body Request w auth:** po `request.text()`/jsonBody oryginalny Request ma zużyty strumień. Utworzenie `new Request(request, ...)` przy logowaniu zgłaszało błąd mimo poprawnych cookies; uwierzytelnianie potrzebuje nowego Request z URL i scalonymi headers. Regresja unit i integracja prawdziwej sesji zapobiegają ponownemu użyciu strumienia. Blokady endpointów tworzących konto muszą działać przed wywołaniem handlera z efektem ubocznym.

- **2026-11-03 — wartość kredytu pakietowego:** wykorzystanie opłaconego kredytu przy aktualnej cenie mentora powodowało rozjazd ledgeru po podwyżce. Snapshot sesji opłacanej kredytem musi korzystać z ceny jednostkowej zapisanego, opłaconego zamówienia pakietu. Regresja realnego PostgreSQL: pakiet po180PLN, zmiana oferty na240PLN, sesja nadal180PLN.
- **2026-11-03 — wyścig wygaśnięcia holda i Checkout:** zewnętrzne utworzenie Checkout może zakończyć się po transakcji `expireHolds`. Sam worker wygaszający hold nie zna wtedy jeszcze sesji operatora. Sprawdzone rozwiązanie: `attachCheckout` dla już wygasłego holda również atomowo zapisuje zadanie wygaśnięcia Checkout; idempotencja operatora chroni ponowienia. Regresja integracyjna odtwarza kolejność expire→attach.

- **2026-11-03 — Request po odczycie body:** po `jsonBody(request)` konstrukcja nowego `Request` na bazie zużytego requestu przerwała logowanie503. Do odczytu sesji przekazuj wyłącznie URL i scalone nagłówki/cookies albo przygotuj kopię przed odczytem body. Regresja realnego auth obejmuje rejestrację, weryfikację, login i reset z unieważnieniem sesji.
- **2026-11-03 — pełny dump a rozszerzenia PostgreSQL:** dump ograniczony `--schema` pominął `btree_gist`, więc odtworzenie exclusion constraint nie działało. Lokalny drill używa pełnego dumpu nowej bazy, zachowuje domyślny schemat public i odtwarza do oddzielnej bazy, sprawdzając rozszerzenie i constraint. Wynik lokalny nie dowodzi PITR/RPO/RTO hostingu.
- **2026-11-03 — lookup zadania a paginowana lista:** worker wyszukiwał konkretny order przez pierwsze100pending; stare nieopłaconeholdy zasłaniały nowe i zadanie było fałszywie ACKowane. Konkretny job wymaga nazwanej metody lookup poID; reconciliation ma kursor i kontrolę postępu. Regresja PostgreSQL z ponad100zamówieniami oraz zliczanym gateway sprawdza oba przepływy.
- **2026-11-03 — równoległe E2E i wspólne zasoby:** desktop/mobile używały tego samego pierwszego slotu i mogły wywołać prawidłowy409, który psuł test. Fixture wybiera rozłączne przedziały według projektu; nie maskujemy konfliktu retry ani pominięciem asercji. Weryfikować oba projekty równolegle.

- **2026-11-03 — wybór źródła płatności przed wywołaniem operatora:** samo checkoutId pojawia się za późno, by chronić wyścig PSP kontra kredyt. Sprawdzone rozwiązanie: atomowo zapisać niezmienny checkout_mode i outbox pod blokadą booking/payment, zanim gateway wystartuje; osobny snapshot nadmiarowego obciążenia chroni właściwe rozliczenie sesji. Niezależna regresja PostgreSQL potwierdziła queued/in-flight i równoległy wybór, deduplikację dodatkowego zwrotu i niezmienione zarobki.
- **2026-11-03 — pochodzenie dostępności i snapshoty migratora:** wycofanie reguły musi unieważnić jej sloty także przy starym bezpośrednim ID; osobne manual_offered/rule_offered zachowują terminy ręczne i historyczne sesje. Migrator dla ręcznych migracji SQL wymaga jawnego snapshot:false zarówno w programmatic, jak i CLI. Niezależnie sprawdzono usunięcie reguły/wygaśnięcie, upgrade/rerun w read-only CWD i brak nowych snapshotów.

- **2026-11-03 — prywatne zamówienie a wspólna sesja:** zabezpieczenie orders jako owner-only ujawniło, że pokój mentora pobierał niewłaściwy zasób. Sprawdzone rozwiązanie: participant GET sessions/id korzysta z istniejącej polityki zasobu i centralnej projekcji usuwającej Checkout dla mentora; orders pozostaje prywatne. Niezależna regresja BetterAuth/PostgreSQL sprawdza join i odczyt owner/mentor/outsider, a końcowy E2E objął pokoje obu uczestników i prywatne notatki.
- **2026-11-03 — Next Request.url przy bind0.0.0.0:** produkcyjny E2E pokazał, że wewnętrzny URL nie zachowuje nazwy localhost klienta; użycie go do bramki demo zwracało404. Sprawdzone rozwiązanie: ścisła walidacja standardowego Host jako loopbackauthority, fallback do URL tylko przy braku Host, bez zaufania X-Forwarded-Host; bramki APP_MODE i cookie owner pozostają. Niezależna regresja dwóch właścicieli, obcych/pustych hostów i production potwierdza brak obejścia. Równoległe E2E muszą izolować syntetycznych klientów za modelem zaufanego proxy: signup3/10s jest prawidłową polityką, której nie należy podnosić dla testów.
- **2026-11-03 — sumy SHA256 a Gitleaks:** nazwa pliku zawierająca api/auth i64znakowy hash na tej samej linii manifestu wywołały fałszywe generic-api-key. Konfiguracja rozszerza defaults i łączy AND: dokładne nazwy trzech manifestów oraz pełną linię filepath→SHA256. Gitleaks.Line może zawierać początkowy newline. Niezależne próby potwierdzają clean dla hashy i wykrywanie api_key w tym samym/innym pliku oraz innej reguły GitHubPAT; nie ignorować całego katalogu evidence.

- **2026-11-03 — mobilny grid i miarodajna regresja viewportu:** tor1fr ma automatyczne minimum; min-content poziomej nawigacji w aside rozszerzało panel i layoutviewport412→835–917px. Oficjalny obraz Playwright potwierdził gridtrack816px przy workspace376px. Sprawdzone rozwiązanie: mobile minmax(0,1fr) i min-width0 aside, z przewijaniem tylko nav. Regresja porównuje scrollWidth do skonfigurowanego page.viewportSize, ponieważ window.innerWidth samo może już być rozszerzone. Normalne kliknięcia obu viewportów przeszły po poprawce.
- **2026-11-03 — wiadomość w textarea nie dowodzi wysyłki:** getByText(message) w E2E dopasowywał draft pola; trace pokazał anulowany POST po natychmiastowej nawigacji i safeSERVICE_UNAVAILABLE. Sprawdzone rozwiązanie: oczekiwać faktycznego POST201, tekstu w artykule historii i ponownego odczytu po reload. Końcowy6/6trace potwierdził201/GET200 dla obu viewportów i brak tych logów. Przy testach nagłówka Host nie używać Node26fetch: echoHTTP potwierdził ignorowanie override; natywne http.request rzeczywiście wysyła Host i pozwala sprawdzić odmowę404.

- **2026-11-03 — Chromium w WSL wymaga także bibliotek systemowych:** obecność cache Playwright nie potwierdza gotowości przeglądarki; agent-browser zakończył start kodem127 z powodu brakującej libnspr4.so. W tym środowisku wcześniej przygotowane biblioteki w /tmp/devmentor-chrome-libs pozwoliły uruchomić rzeczywiste testy przez LD_LIBRARY_PATH, z AGENT_BROWSER_EXECUTABLE_PATH wskazującym zainstalowany Chrome dla agent-browser. Potwierdzenie: integracja przeglądarkowa2/2 i E2E6/6. To tymczasowa konfiguracja środowiska; na nowym hoście stosuj instalatory bibliotek z README, a przy błędzie sprawdź ldd oraz stderr zamiast pomijać test.

- **2026-11-03 — odświeżanie wiadomości w tle:** zwykły reload zasobu przełączał loading i przy błędzie usuwał historię, więc nie nadawał się do wymaganego pollingu. Opcjonalny cykl po zakończeniu odczytu zachowuje dane/kursor/draft, nie nakłada żądań, pauzuje dla hidden/starszej historii i anuluje stare scope. Weryfikacja: siedem regresji fake-timer oraz rzeczywisty E2E odpowiedzi drugiego uczestnika bez reload na desktop/mobile; przy kolejnych zmianach sprawdzaj artykuł historii i zachowany szkic, nie tylko liczbę żądań.
